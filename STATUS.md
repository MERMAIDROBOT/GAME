# First milestone — October 5, 2026

Kelly Slater's Pro Surfer is the first real-disc test case. The reusable pipeline source contains no retail assets, executable bytes, extracted symbol inventory, or generated game code. These remain in the private workspace.

## Verified results

- All 328 disc files, totaling 4,597,704,044 bytes, preserved and locally checksum-verified.
- PS2Recomp analyzer and recompiler built natively on Apple Silicon with Apple Clang 17.
- Public tool revision and seven dependency revisions recorded in the toolchain lock.
- The single `prepare` command passed verification, ELF inspection, analyzer configuration, and C++ translation using the actual local game input.
- 9,078 functions processed: 8,800 translated, 278 emitted as stubs, none skipped, zero decode failures.
- 9,079 C++ translation units produced, including registration code.
- Upstream report: zero unhandled instructions and zero reported errors, but 3,484 control-flow warnings. Those warnings concern unresolved indirect branches and fallback entry promotion; a clean decoder report does not prove runtime correctness.
- 12 representative generated files passed native C++ syntax checks, including registration and large generated functions. This is not a full native build or a linking test.
- Six synthetic-input tests passed: resumable imports, recovery from a reader dropout, tamper detection, rejection of mismatched inputs, traversal/symlink rejection, and malformed ELF rejection.

No game data was uploaded or published. Public tool setup used downloads. Game processing used local files. Nested OS network sandboxing is unavailable in this Codex host; the processing source was reviewed for network operations and the wrapper explicitly reports the limitation.

## Next milestones

1. Integrate and build a native host runtime, keeping its public dependencies separate from private game processing. Investigate the indirect-branch warnings and library bindings rather than treating automatic stubs as validated behavior.
2. Attempt first boot with local asset access and diagnostic traces. Resolve startup, threading, memory, IOP, file, and graphics dependencies as observed.
3. Reach menus and gameplay, validating input, wave simulation, rendering, sound, and saving against the original game.
4. Package a local macOS application and add an import flow that does not bundle game data into distributable source.
5. Validate a second legally supplied disc. Generalize only steps proven to transfer across titles; keep region/build/runtime fixes in per-game adapters.

There is not yet a universal repeatable disc-to-playable-app pipeline. This milestone makes its preservation-through-translation portion repeatable through one interface while retaining multiple upstream projects as pinned dependencies.
