# Recover → compare → retain → reuse

The shared C++ and macOS products now have an executable, bounded recovery
workflow. It reads an owned disc executable locally, derives a readable expression
and memory effects, compiles them to C++, executes the original instructions from
the same inputs, and compares the results. Passing recipes can be retained in a
private cross-title bank. Reuse always repeats the target's comparisons.

This is a first integrated integer-leaf path, not an arbitrary-function decompiler,
a hardware-certified oracle, a whole-game converter or an automatic runtime patch.

## Original-execution qualification

```sh
python3 run.py oracle-check
```

The original-execution backend is the reviewed MIT interpreter from
`danielgomesvieira2000/ps2-port-engine` at
`01a93a35cf6653802970c292feaa11c707a04754`, retained unchanged in `recovery_core/`.
Its manifest preserves source hashes and license. We chose this local Python
backend rather than enable the reviewed Rust oracle's unresolved float model.

The public adapter admits only these nontrapping integer operations: ADDIU,
ANDI/ORI/XORI/LUI; ADDU/SUBU/AND/OR/XOR/SLT/SLTU; immediate SLL/SRL/SRA;
LB/LBU/LH/LHU/LW/LWU; SB/SH/SW; and a final JR RA plus its delay slot.
NOP is the zero-word shift encoding. The maximum is 64 instructions; no other
control flow, calls, floating point, SIMD, division, HI/LO, hardware service or
128-bit operation is admitted. Trapping ADD/ADDI are deliberately excluded.

Every recovery run first checks 25 fixed expected architectural cases covering
this admitted opcode set. The expected values are hand-authored ISA regressions,
not generated by the oracle or symbolic evaluator, and not physical PS2 captures.
The underlying decoder is shared with recovery, so shared decode errors remain a
blind spot; passing fixtures do not qualify the entire upstream interpreter.

Original cases start with fresh registers/RAM, with no external hooks or stubbed
calls. Callee-saved registers, GP/SP/RA are checked. The comparison contract is
V0's full low-64-bit return, exact final RAM and ordered store address/width/value
records. Volatile scratch registers, V1 as a second return, full 128-bit register
results, devices, timing and exceptions are outside this contract. Functions that
change callee-saved state at return are refused rather than silently masked.

Only immutable code plus one explicit, bounded RAM region exist. Unknown accesses,
misalignment, MMIO, exhausted budgets and missing returns fail. Loads after any
store—including a load in the return delay slot—are refused. This is narrower
than upstream's interpreter and prevents its placeholder hardware windows or
external-call stubs from qualifying a recovered function.

## Recover a function

Use an explicit per-game profile with a pinned executable and private storage.
Create a specification **inside that game's private directory**:

```json
{
  "schema": 1,
  "executable_sha256": "<full executable SHA-256>",
  "function": {"address": "00100000", "bytes": 12},
  "cases": [
    {
      "args": ["0000000000000001", "0000000000000000",
               "0000000000000000", "0000000000000000",
               "0000000000000000", "0000000000000000",
               "0000000000000000", "0000000000000000"],
      "memory": {"base": "00008000", "hex": ""}
    }
  ]
}
```

The example illustrates one case; **8–64 distinct explicit cases are required**.
Arguments are the eight integer register arguments, encoded as full hexadecimal
64-bit values. RAM is at most 64 KiB per case, with explicit initial bytes.
Choose actual pointer-valid states and include relevant bounds, signs and alias
cases. Eight different inputs still do not establish exhaustive equivalence.
The executable must match both the specification and any profile pin. Function
bytes must fit in one file-backed executable PT_LOAD segment.

```sh
python3 run.py --profile .private/profiles/game-a.json recover-function \
  --spec recovery/leaf.json --name leaf-1 --bank @shared
```

Outputs go to a new owner-only `analysis/function-recovery/leaf-1/` in private
storage: recipe, readable C++, native executable, compile/execution logs and a
fingerprinted report. A C++20 compiler and UBSan are required. Cases run against
actual compiled C++, not merely the symbolic tree's evaluator. A source or input
change during the run prevents retention. Existing runs are not overwritten.

RAM loads/stores in C++ go through checked guest-memory helpers, never native
pointers made from guest addresses. All store addresses/values and the return
are evaluated before applying stores. This preserves values originally loaded
before aliased writes. Unknown expression nodes cannot inject native code.
The record contains adapter/core/fixture/runner hashes, executable/function/case
identity, compiler/version/flags, source/binary hashes and comparison counts.

## Private cross-title reuse

`@shared` selects `.private/recovery-bank/` in the engine checkout. It is local,
ignored by Git and excluded from source packaging. A normal private-relative
bank path is also supported. Do not publish records: they contain recovered
recipes and original function bytes. Source and executable originals are retained.

```sh
python3 run.py --profile .private/profiles/game-b.json find-recovery-candidates \
  --spec recovery/leaf.json --bank @shared
python3 run.py --profile .private/profiles/game-b.json recover-function \
  --spec recovery/leaf.json --name reused-1 --bank @shared \
  --reuse <full candidate SHA-256>
```

Matching supports exact instruction bodies across different executable addresses,
and a conservative LUI/possible-low-immediate normalization inspired by GT4's
cross-game candidate search. The adaptation kills tracked high registers when
an instruction overwrites them. Normalized matches remain ambiguous candidates,
not proved relocation equivalence or authorization to activate code.

For a genuinely relocated complete address constant in a recovered recipe,
supply explicit private bindings:

```json
{"00018000": "00028000"}
```

Add `--bindings recovery/bindings.json` with `--reuse`. Only complete constant
nodes are changed; unused mappings fail. Partial high/low inference, call-target
rewriting, original compiler matching and arbitrary struct-layout changes are
not implemented. Unchanged or incorrectly relocated candidates must still pass
fresh original/native comparisons on the destination binary. Failed or faulting
reuse is not retained or activated.

Records are content-addressed and tied to the model version. Tampering or model
drift requires requalification. The adapter accepts only a bounded data recipe,
not arbitrary Python, external shell commands or saved native source strings.

## What passing means

A successful report says `agreement_on_cases` and lists every compared case.
There are no skipped-case passes. It always sets `universal_equivalence: false`,
`hardware_rerun: false` and `promoted_to_runtime: false`. This stage does not
replace generated game functions automatically. Later integration still needs
correct ABI/state contracts, broader oracle evidence and player-route regression.

Tests execute real original instructions and real compiled C++. Negative controls
plant wrong returns and stores, omit output rows, corrupt bank records, change
inputs during execution, remove relocation bindings and violate memory/ABI rules.
Cross-title fixtures demonstrate exact-body transfer at a different entry address
and explicit relocated-data transfer. These fixtures contain no retail inputs.
